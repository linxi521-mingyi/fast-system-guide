后续需要的数据

分三类：持续完善的监测数据、待接入的研判运维数据、孪生计算边界条件。

A · 监测类（已有，需理顺）

  • 节点 / 索网温度时序（统一测点目录）
  • 索力时序与极值、单位与有效区间
  • 断丝告警流水与索段 ID 稳定对应
  • 三维几何与测点坐标版本化

B · 研判运维类（待接入）

  • 诊断结论：对象 / 类型 / 等级 / 置信度 / 建议 / 定位
  • 寿命：剩余年限 / 风险 / 趋势
  • 健康：综合指数 + 子系统评分
  • 备件主数据与出入库流水
  • 运维事件日志、发布通报与回执

C · 孪生边界（中长期）

  • 促动器油压、活塞伸出量
  • 馈源舱位置坐标
  • 相对基准态位移（可放大显示）
  • 有限元求解结果云图数据

接口清单

现网已用接口 + 建议新增业务接口。统一建议 REST + JSON，对象 ID / 等级枚举全站一致。

已存在（监测主链路）

接口作用状态
GET /api/login · /api/me登录与会话已用
GET /Index/data三维结构 / 传感器基础数据已用
GET /Index/chart1边缘索温度曲线需修测点映射
GET /Index/chart2 · chart3温度均值 / 索网内曲线已用
GET /Index/getHeatMapData温度云图已用
GET /Index/monthDays日历有数日期已用
GET /alarm · /alarm/data告警状态与历史已用
GET /alarm/downloadHistory 等告警导出已用

建议新增（替换演示数据）

接口约定建议： 索段 / 促动器 / 钢丝绳编码与三维、告警、诊断共用一套 ID； 告警等级 0正常 / 1疑似 / 2高度疑似 / 3干扰； 时间格式统一；无数据返回空数组而非 500；写接口需登录态。

后续优先级

  1. P0 理顺边缘索等测点映射，三大监测稳定可演
  2. P0 固化告警类型与索段 ID 规范
  3. P1 接入诊断 / 寿命 / 健康模型结果接口
  4. P2 备件、发布、日志对接真实业务库
  5. P3 有限元 / 孪生求解服务在线化

讲解收束三句话

  1. 现在已经做成：统一门户 + 温度 / 索力 / 断丝三维监测与告警追溯。
  2. 界面已经铺好：诊断、寿命、健康、备件、日志、发布按运维链条可演示。
  3. 下一步最需要：模型标准数据与接口，以及测点编码、告警等级等共同语言。
