主要功能如何实现

面向专家可能追问的技术路径：整体架构、三维云图、告警、演示模块如何接真数据。表述以当前发布版为准。

整体架构（一句话）

本机运行 FASTServer.exe（.NET）提供 Web 服务（默认端口 1080）： 一边托管 page/ 静态前端，一边对外提供 /api/*、/Index/*、/alarm* 等接口； 监测与告警数据来自云端 MySQL，由服务端查询后以 JSON 返回浏览器。

浏览器页面 → FASTServer 本地服务 → 云端监测 / 告警库

1. 登录与门户

实现要点：登录页调用 /api/login；各业务页通过 auth.js 请求 /api/me 校验会话，未登录则跳转登录页。

门户：ui/index.html 以九宫格卡片进入各模块；全站顶栏由 nav-nine.js / nav-nine.css 注入九大功能及二级菜单。

可能追问：权限如何做？——当前为运维账号登录态；更细角色权限可在服务端会话层扩展。

2. 温度场三维监测

实现要点：indexTemp.html 使用 Three.js 加载反射面三维模型；测点 / 结构基础数据来自 /Index/data；云图着色数据来自 /Index/getHeatMapData 等接口返回的温度数组，按色标映射到网格。

曲线面板：ECharts 请求 /Index/chart1~3 绘制边缘索 / 均值 / 索网内温度过程；日历有数日期由 /Index/monthDays 提供；底部时间轴支持历史回放。

可能追问：云图是实时算的吗？——当前为库内监测时序驱动前端着色展示；有限元在线求解属后续孪生深化方向。

3. 索力三维监测

实现要点：indexForce.html 同样以三维模型为底，索段按索力大小着色；左侧结构索力曲线与「极值排列」来自对应索力数据接口；右侧控制台切换模型显示与视角。

可能追问：与温度场如何复用？——同属「三维底图 + 云图/着色 + 侧栏图表」模式，页面与接口按业务拆分，视觉与交互体系统一。

4. 断丝预警与告警记录

实现要点：indexAlarm.html 按告警状态对索段着色（绿 / 黄 / 红 / 蓝）；列表请求告警接口展示最近记录，点击可与模型对照。alarmBoard.html 做统计卡 + 明细表；下载页调用 /alarm/downloadHistory 等导出。

可能追问：四级状态谁定义？——前端按约定枚举展示；等级规则与传感器判定在采集 / 告警侧产生，系统侧重汇聚展示与追溯。

5. 诊断 / 寿命 / 健康等扩展模块

实现要点：页面采用「左侧结论清单 + 中间三维底图（iframe 嵌入 index30.html）+ 右侧说明」布局，公共样式与钉点逻辑在 module-3d.css / module-3d.js。当前列表数据来自 ui/js/mock.js 前端演示数据。

可能追问：如何换成真结果？——保持现有 JSON 字段约定，新增 /api/diagnosis、/api/life、/api/health 等接口，前端改请求源即可，不必重做交互骨架。

6. 备件 / 日志 / 发布

实现要点：备件页为库存台账、KPI、出入库登记的前端流程；日志页支持事件列表与一键生成日报文本；发布页为标题正文编辑与演示发布结果。当前以页面内逻辑 / 演示数据为主。

可能追问：能否对接现有物资或 OA？——可以。将出入库、发布改为调用业务系统 API，本系统作为运维统一入口承接展示与操作。

专家常见追问 · 简答备忘

数据存在哪里？本机还是云端？

监测时序、告警历史等业务数据在云端 MySQL；本机 FASTServer 负责鉴权、查询聚合与静态页托管。演示模块（诊断等）暂不写库。

三维模型与传感器如何对应？

通过测点 / 索段编码及坐标（或通道映射）与模型节点关联；基础清单由 /Index/data 等接口下发。编码不一致会导致局部曲线或着色为空，需统一测点目录。

为什么有的曲线有数、有的为空？

以边缘索温度曲线为例：接口可通，但测点在新旧传感器表映射不一致时，会返回空序列。属配置 / 映射问题，不是前端渲染失效。同页其它曲线有数可作对照。

数字孪生是否已做在线有限元？

当前重点是「监测数据三维可视化 + 运维功能承载」。编制说明中的油压、舱位等边界条件驱动有限元计算，属于后续对接计算服务的方向。

前后端如何划分？改界面会不会动数据库？

页面与样式在 page/；业务接口在 FASTServer 程序集。一般美化与布局只改前端静态文件；改测点映射或查询逻辑才涉及服务端 / 库表。

如何保证演示边界说清楚？

监测与告警：真实链路。诊断、寿命、健康、备件、日志、发布：界面与交互已就绪，数据为演示或待接业务。汇报时按成熟度表说明即可。

后续需要的数据

分三类：持续完善的监测数据、待接入的研判运维数据、孪生计算边界条件。

A · 监测类（已有，需理顺）

  • 节点 / 索网温度时序（统一测点目录）
  • 索力时序与极值、单位与有效区间
  • 断丝告警流水与索段 ID 稳定对应
  • 三维几何与测点坐标版本化

B · 研判运维类（待接入）

  • 诊断结论：对象 / 类型 / 等级 / 置信度 / 建议 / 定位
  • 寿命：剩余年限 / 风险 / 趋势
  • 健康：综合指数 + 子系统评分
  • 备件主数据与出入库流水
  • 运维事件日志、发布通报与回执

C · 孪生边界（中长期）

  • 促动器油压、活塞伸出量
  • 馈源舱位置坐标
  • 相对基准态位移（可放大显示）
  • 有限元求解结果云图数据

建议新增（替换演示数据）

接口约定建议： 索段 / 促动器 / 钢丝绳编码与三维、告警、诊断共用一套 ID； 告警等级 0正常 / 1疑似 / 2高度疑似 / 3干扰； 时间格式统一；无数据返回空数组而非 500；写接口需登录态。
